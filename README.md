# Estimate App

Angular frontend bootstrap for Estimate Agent (AT-207). [ADR 0001](https://github.com/oicrruf/estimate-api/blob/develop/docs/adr/0001-arquitectura-inicial.md) defines the architecture. The current UI is an accessible, responsive empty workspace; project features and full bilingual UI follow later issues.

## Local setup

Node `24.15.0` or newer compatible Node 24 and npm 11.19.1. Run `npm ci`, `npm start`, and `npm run check`. The latter runs lint, TypeScript checks, unit tests, contract drift tests, OpenSpec strict validation, and production build. No account or secret is needed. Do not place runtime secrets or Supabase privileged keys in this public app.

## API contract

The API owns the canonical deterministic OpenAPI 3.1 JSON. AT-207 freezes only `GET /health` (`operationId: health`, 200 JSON `{ "status": "ok" }`, info version `0.1.0`). `contracts/openapi.json` is the tracked reference; `src/app/api/health.generated.ts` is generated by `npm run contract:generate`. `npm run contract:check` catches a stale generated file and exercises positive/negative drift. The [contract sync procedure](docs/contract-sync.md) records how to advance both repos together. CI checks the current `estimate-api/develop` HEAD against the pinned squash SHA `6ecc9a9c5d6ba6355e3332f8b6533c81ed878b74`, verifies its deterministic FastAPI export, byte-compares its artifact with the app reference, and checks generated TypeScript. This catches both upstream movement and contract drift; a local-copy-only check cannot prove cross-repo sync.

## Workflow

Use OpenSpec's `spec-driven` flow: proposal → specs/design → tasks → apply → validate/verify → archive. `openspec/specs/` contains current specifications; `openspec/changes/archive/` retains the AT-207 trail. See [AGENTS.md](AGENTS.md) for agent conventions and [branch policy proposal](docs/branch-policy-proposal.md) for proposed protected Git Flow settings. CI does not enable branch protection or deploy an app. Synthetic fixtures only.
