It pins each artifact's bytes, verifies the frozen health/intake paths and their existing schemas in both phases, and checks the project list, project read, and authenticated scope-preview operations explicitly in the five-operation phase. `scripts/contract-phase-test.mjs` runs both phases and synthetic route, schema, security, and idempotency drift cases. The live lineage gate compares the current Git-tracked OpenAPI against the integrated API commit; the generator produces no changed health client bytes for this transition.

`src/app/api/scope-review-preview.ts` describes `POST /v1/projects/{projectId}/scope-review-preview`. A caller must provide a typed authenticated project editor context, a 1–100 character idempotency key, an explicit API base URL, and an injected fetch transport. The client sends Bearer authorization and omits browser credentials. It validates a nonblank brief of at most 4,000 Unicode code points and requires the response to name the same project and explicitly remain pending, review-required, non-persisted, and not commercially ready. A 404 maps only to “not found”; it does not reveal whether a project is absent or membership was revoked. HTTP and network failures return bounded codes without exposing response bodies.

The reviewed proposal schema requires `status` and allows `availableQuantity` to be omitted, `null`, or a nonnegative integer. The client preserves an omitted field; it does not fabricate stock information. Unknown proposal fields and invalid quantities are rejected.

The home workspace now contains a local composer component behind an optional `SCOPE_REVIEW_RUNTIME` injection token. The default app configuration provides no value for that token, so the original empty workspace remains visible and no preview request can occur. The adapter interface supplies an API base URL, a session-derived editor context, an opaque `contextVersion` signal that changes on account/project switches, and a transport; it is never populated from a form field or a fixed project ID. The component resolves the context again before each request, clears the prior brief, results, and retry keys on context changes, rejects late edit/submit events and responses from an older context, blocks concurrent sends, and shows only validated pending responses as Angular text. A 401, 403, or generic 404 clears the brief and result and disables further sends until access is rechecked. After an account or project switch, the editor must enter a fresh brief before sending. Transient retry of the same draft reuses its idempotency key; editing the draft creates a new key.

This is local integration evidence, not an enabled user feature. Unit tests use synthetic editor contexts and injected fetch only. The earlier visual composer candidate remains separate because it was based on an older branch and had a fixed project ID. These tests do not verify sign-in, a live API call, a hosted service, or project membership.

Before enabling the compositor, a real auth adapter must derive the active project and editor context from a verified session, refresh or revoke it correctly, and supply a bounded API transport. The backend must independently confirm membership and role on every request. An authenticated browser and backend integration test must verify those conditions and idempotent retry before installing the runtime provider in `app.config.ts`. Future API contract changes follow [contract synchronization](contract-sync.md).
